## Короткие ответы на вопросы защиты

- **Бинарный файл vs текстовый в Python:** текстовый режим (`r`, `w`) декодирует байты в `str` с заданной кодировкой и может менять переводы строк; бинарный (`rb`, `wb`, `xb`) работает с `bytes` без преобразований. Для хеширования нужен именно `rb`.
- **Зачем `with`:** он гарантирует закрытие файла (и сброс буфера записи) даже при исключении внутри блока.
- **Почему режим `w` опасен:** он молча перезаписывает (обрезает до нуля) уже существующий файл. Режим `x` (`xb`) создаёт файл только если его нет, иначе вызывает `FileExistsError`.
- **Чем `*.txt` отличается от проверки формата:** шаблон смотрит только на имя/расширение. Файл с именем `.txt` может содержать что угодно; реальный формат определяется содержимым (здесь его косвенно подтверждает размер и SHA-256).
- **Почему нельзя сразу сохранять содержимое ZIP:** архив может содержать путь с `..`, чужое имя получателя, неверный размер или подменённые данные. Пока проверки не пройдены, запись на диск недопустима.
- **Подтверждает ли хеш личность отправителя:** нет. SHA-256 подтверждает только целостность (байты не изменились). Идентичность отправителя должна подтверждаться подписью/аутентификацией; здесь поле `sender` — простое ключевое слово из манифеста.
- **Последовательный обход:** `rglob("*")` проходит каталог рекурсивно, по одному элементу за раз; для каждого файла «на месте» проверяются условия и собирается запись, поэтому не нужно загружать всё дерево в память (кроме итогового списка).
